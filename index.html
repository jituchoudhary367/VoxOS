Problem Statement

Assistants talk. They rarely do the work.

  • ×Chat wrappers. Most assistants answer questions but cannot touch your files, apps or browser.
  • ×No planning. "Do A, then B, and also C" gets flattened into one confused action.
  • ×No verification. They say "done" without checking that anything happened.
  • ×Invented facts. Links, numbers and confirmations that no tool ever returned.
  • ×No brakes. An agent with shell and file access can do real damage on a misheard word.
What this costs the user

"I asked it to send the file. It said it did. It didn't."

Trust is the product. An assistant that controls a computer has to plan, check its own work and ask before anything risky.

Our Answer

Say it, or type it. Vox does it on your PC.

Agent Responsibilities

Each agent has one job

Agent 01
Listener
Understands the request. Whole-sentence rules catch everyday commands instantly. Anything else goes to a small fast model that names the intent and its arguments.
Agent 02
Coordinator
Splits a request only where the parts can run in parallel, and gives each goal just the tool families it needs. Knows recent turns and open browser tabs.
Agent 03
Workers
One per goal. Act, observe, decide again. The Executor runs each tool and the Overseer verifies the result. A worker can ask you a question or stop when blocked.
Agent 04
Synthesizer
Writes one reply from what the workers actually found. Links and facts that no tool returned are removed in code, not left to the model's honesty.
What Vox Can Do

85 tools across 15 families

Files & documents
Find, read, move, rename, organize a folder, zip and unzip. Write Word, Excel, PDF and CSV. Delete goes to the Recycle Bin.
Apps & desktop
Open and close apps, manage windows, clipboard, keyboard and mouse. Click buttons by name through Windows UI Automation.
Browser & web
Search, open pages, read and extract, fill forms, control media. One tab per task, or attach to your own Chrome.
System
Volume, brightness, dark mode, Wi-Fi, Bluetooth, lock, battery, RAM, drives, and which app is using the most memory.
Google & messaging
Gmail search, read, draft and send. Calendar events. Drive search and read. WhatsApp and email drafts from saved contacts.
Time, memory & more
Timers, reminders and daily routines. Calculator and Python. Long-term memory. "What's on my screen?" through a vision model.

Plus any external tool server through the Model Context Protocol (MCP). Read-only tools run freely; everything else needs approval.

Safety & Trust

Brakes are built into the code, not the prompt

  • 1Risk engine. Every tool call is classified. High-risk actions show an Approve / Deny card. Dangerous shell patterns are blocked outright.
  • 2Permissions. Unknown tools are denied by default. Executor and tool runner both enforce it.
  • 3Private paths. Keys, .env files, dot-folders and AppData stay unreadable.
  • 4Passwords never reach the model. Logins live in Windows Credential Manager and are filled only on the matching https site.
  • 5Nothing irreversible without a yes. Sending mail, inviting people, closing apps, final "Buy" clicks.
  • 6Grounded replies. A link in an answer must appear in tool output, or it is removed.

Limitations

Where Vox still falls short

Model quota
Free-tier limits (about 8K tokens a minute per key and model) slow down heavy web tasks. Vox paces itself and rotates keys, but the ceiling is real.
Complex websites
Shopping flows with ads, pop-ups and bot checks are unreliable. Search and reading work; full checkout does not yet.
Wake word
No trained "Hey Vox" model yet, so a stock wake word stands in. The hotkey is the dependable trigger today.
Setup & platform
Windows only, and it still needs a developer setup with API keys. There is no one-click installer.

The risk classifier alone catches 68% of risky commands on unseen data; the approval gate lifts that to 94% at the cost of more prompts.

Conclusion

Vox shows that an assistant can be trusted with a real computer when understanding, planning, acting and checking are separate jobs, simple requests skip the model entirely, and every risky step waits for the user.
